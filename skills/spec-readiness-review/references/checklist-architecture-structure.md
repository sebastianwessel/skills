# Architecture And Structure Checklist

- General file/folder structure by domain/topic, without exhaustive file lists.
- Ownership boundaries, nested structure expectations, and boundaries that must
  not gain unrelated domain logic.
- Public entrypoints, adapters, migrations, runbooks, operational assets, and
  generated outputs placed in the intended structure.
- Shared/reusable module, helper, component, service, and package placement.
- Custom abstractions justified by reuse, cohesion, or complexity reduction.
- N/A evidence for layers outside implementation scope.
